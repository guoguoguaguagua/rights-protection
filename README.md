# telecom-appeal-checklist

向运营商申诉需求的可复用清单：通话前设止损线、通话中留痕确认、和解时限定边界、事后做三行复盘。

> 本仓库为通用流程清单，不构成法律意见。申诉应基于真实事实，遵守平台规则和法律法规，不鼓励恶意投诉。

## 适用场景

- 话费异常、乱扣费、套餐被变更
- 宽带/流量/信号故障反复不解决
- 客服承诺未兑现、退款不到账
- 对客服处理方案不满意，需要判断继续追还是止损

也可泛化到电商售后、快递、航司酒店、物业、水电燃气、会员自动续费等消费申诉场景，但话术和留痕项需按场景调整。

## 核心原则

- 方案是工具，你是决策者：接受和解不等于软弱，追到底也不等于唯一正确。
- 先分层诉求，再谈金额：别被补偿金额带着走。
- 关键信息必须留痕：工号、工单号、方案性质、到账时间、是否最终处理。
- “不再追究”要限定范围：只针对本次问题，不等于放弃其他权利。
- 止损线前置：通话前就想好什么条件下接受方案。

## 使用方法

1. 通话前读 `templates/demand-layers.md`，写下必须/希望/可放弃。
2. 通话中按 `SKILL.md` 的五步流程走。
3. 结束前对照 `checklists/call-checklist.md` 逐项确认。
4. 收尾用 `templates/closing-script.md` 的话术限定范围。
5. 事后按 `SKILL.md` 的三行复盘记录。

## 目录

- `SKILL.md`：核心流程
- `checklists/call-checklist.md`：通话结束前必问清单
- `templates/demand-layers.md`：诉求分层模板
- `templates/closing-script.md`：收尾与限定范围话术
- `examples/demo-redacted.md`：脱敏示例

## 脱敏要求

上传或分享前，删除/替换：手机号、客服工号、工单号、订单号、通话录音、截图、地址、身份证、银行卡、真实姓名、通话记录。不要提交 `recordings/`、`screenshots/`、`exports/`、`personal-notes/`。
